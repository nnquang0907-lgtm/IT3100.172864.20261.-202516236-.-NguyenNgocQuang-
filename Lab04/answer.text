No, Java does not allow this. Java tells overloaded constructors apart only by their parameter lists: the number, the types, and the order of the parameters. 
Parameter names don’t count. Here both constructors have the signature DigitalVideoDisc(String), so the compiler can’t tell which one to call for new DigitalVideoDisc("Action").

Assignment 10:
1. Why titles stay the same after swap(jungleDVD, cinderellaDVD):
Java is pass-by-value. The swap method only swaps local copies of the reference variables (o1 and o2) inside its own scope, 
leaving the original jungleDVD and cinderellaDVD references in main untouched.   
2. Why jungleDVD's title changes after changeTitle(...):
The parameter dvd holds a copy of the reference pointing to the same object in memory as jungleDVD. 
Calling dvd.setTitle() directly mutates the state of that underlying object.
